Importing and Tidying Data with the Tidyverse

Learning goals

By the end of this tutorial, you should be able to:

  1. import a CSV file with readr::read_csv();
  2. inspect an imported dataset with glimpse();
  3. identify the observational unit of a dataset;
  4. explain the three rules of tidy data;
  5. use pivot_longer() to reshape data; and
  6. recognize when column names encode multiple variables.

Part 2: Tidy the biomass data

A dataset is tidy when:

  1. each variable is a column;
  2. each observation is a row; and
  3. each value is a cell.

In biomass_wide, years are stored as column names. Biomass is spread across several columns even though it is one measured variable.

The observational unit we want is:

One stock observed in one year.

A tidy version should contain the variables:

  • region
  • stock
  • year
  • biomass_t

Lengthen the data

Use pivot_longer() when information that belongs in rows is spread across columns.

First, look at the documentation for pivot_longer(). You see the description, usage, and examples. What are some of the listed arguments?

? pivot_longer()

Now let’s use pivot_longer() to reshape the biomass_wide dataframe. We will want to provide which columns we want to pivot into longer format (cols =) the name of the new column that will contain the original column names (names_to = "year"), and the name of the new column that will contain their values (values_to = "biomass_t").

We will also start using the pipe |> operator, which takes the result on its left and passes it into the function on its right. We will learn more about the pipes next week in the data wrangling tutorial. Pipes have made coding simpler and easier to read. In the below example, we take the biomass_wide dataframe, pipe (or pass) it into the function pivot_longer().

biomass_long <- biomass_wide |>
  pivot_longer(
    cols = starts_with("20"),
    names_to = "year",
    values_to = "biomass_t"
  )

Each file contains the same variables but different observations. Stack them with bind_rows(). bind_rows() is a tidyverse (actually {dplyr}) function that binds any number of data frames together by row (i.e., stack them). The output will contain all columns that appear in any of the inputs. (There is also a function bind_cols).

Here, we combine the three dataframes together and then pipe the output into another function, rename_with to convert all column names to lowercase (using str_to_lower).

lotr_wide <- bind_rows(
    fellowship,
    two_towers,
    return_king) |>
  rename_with(str_to_lower)

Warningbind_rows() is not a join

Use bind_rows() to stack similar observations vertically. Use a join (e.g., left_join() [which we will learn about later]) when separate tables contain different variables that must be matched using an identifier.

Use the tidy data

To illustrate how useful tidy data is for working with the {tidyverse} packages, we will produce a summary of the number of words spoken by males and females. group_by is a function that groups a dataframe by the specified variable(s) so operations can be performed on a per-group basis. summarize (or summarise as the package developer is British) creates a new data frame that returns one row for each combination of grouping variables. If no grouping variables, the output will have a single row summarizing all observations in the input. Below, we use group_by and summarize to create a new column total_words.

lotr_tidy |>
  group_by(gender) |>
  summarize(
    total_words = sum(words),
    .groups = "drop"
  )
# A tibble: 2 × 2
  gender total_words
  <chr>        <dbl>
1 female        2428
2 male         18817

Step 2: Separate the encoded variables

The first character of demographic indicates gender, while the remaining characters contain the age code. We can separate these components using separate_wider_regex() from the {tidyr} package. This function splits a character column into multiple columns based on regular expression patterns. Regular expressions are patterns used to match specific arrangements of characters within text. Here, "[mf]" matches either "m" or "f", and ".*" matches all remaining characters. Related functions can instead split values at delimiters, such as commas, or at fixed character widths.

tb_tidy <- tb_long |>
  separate_wider_regex(
    demographic,
    patterns = c(
      gender = "[mf]",
      age = ".*"
    )
  )

Part 5: Exporting data frames

Use write_csv() from the {readr} package to save a data frame as a CSV file. The first argument is the data frame to save, and the second is the file path and filename. Unlike base R’s write.csv(), write_csv() does not add row names as an extra column.

# create a path for the output file
output_file <- file.path(
  data_file_path,
  "lotr_tidy.csv"
)

# save the tidy data as a CSV file
write_csv(
  lotr_tidy,
  output_file
)

# check that the file exists

Optional extension: Widening data

pivot_wider() performs the opposite transformation. It takes values from rows and uses them to create columns.

words_by_gender <- lotr_tidy |>

  summarize(
    total_words = sum(words),
    .groups = "drop"
  )

words_by_gender |>
  pivot_wider(
    names_from = gender,
    values_from = total_words

## Part 1: Import and inspect data {#sec-import}

A CSV is a plain-text file in which columns are separated by commas. We use `read_csv()` to import the `stock-biomass-wide` dataframe and assign the result to an object.

```{r}

biomass_wide <- read_csv(

biomass_wide
```

The first argument to `read_csv()` gives the **path** to the file. With the `{here}` package, we list all folders after the root folder (here, `course-hub/`).

The second argument is the `na` argument, which identifies entries that should be treated as missing values. In this file, a period (`.`) means that no value was reported. Usually, a cell is left blank if no value is reported.

## Part 2: Tidy the biomass data {#sec-biomass}

A dataset is tidy when:

1.  each variable is a column;
2.  each observation is a row; and
3.  each value is a cell.

In `biomass_wide`, years are stored as column names. Biomass is spread across several columns even though it is one measured variable.

The observational unit we want is:

> One stock observed in one year.

A tidy version should contain the variables:

- `region`
- `stock`
- `year`
- `biomass_t`

### Lengthen the data

Use `pivot_longer()` when information that belongs in rows is spread across columns.

First, look at the documentation for `pivot_longer()`. You see the description, usage, and examples. What are some of the listed arguments?

```{r}
? pivot_longer()
```

Now let's use `pivot_longer()` to **reshape** the `biomass_wide` dataframe. We will want to provide which columns we want to pivot into longer format (`cols = `) the name of the new column that will contain the original column names (`names_to = "year"`), and the name of the new column that will contain their values (`values_to = "biomass_t"`).

We will also start using the pipe `|>` operator, which takes the result on its left and passes it into the function on its right. We will learn more about the pipes next week in the data wrangling tutorial. Pipes have made coding simpler and easier to read. In the below example, we take the `biomass_wide` dataframe, pipe (or pass) it into the function `pivot_longer()`. 

```{r}
biomass_long <- biomass_wide |>
  pivot_longer(
    cols = starts_with("20"),
    names_to = "year",
    values_to = "biomass_t"
  )

biomass_long
```

Read the arguments as a sentence:

> Take the columns whose names start with `20`, put their names into a new variable called `year`, and put their cell values into a new variable called `biomass_t`.

Compare the original and reshaped datasets.

```{r}
biomass_wide
```

```{r}
biomass_long
```

What do you notice?

### Check the result

```{r}
glimpse(biomass_long)
```

What needs fixing? hint: look at the `year` variable type.

```{r}
LOTR_file_path <- file.path(data_file_path, "The_Fellowship_Of_The_Ring.csv")
```

Now that you know about creating file paths, let's read in out datasets. Because we have more than one dataset file, we won't use the above code (`LOTR_file_path`). We will use `file.path` and `data_file_path` in the `read_csv` function. `read_csv` normally prints out a lot of information inferred from the file. You can use the `show_col_types = FALSE` argument to prevent this. 

### Import the three files

```{r}
fellowship <- read_csv(
    file.path(data_file_path,
    "The_Fellowship_Of_The_Ring.csv"),
  show_col_types = FALSE
)

two_towers <- read_csv(
    file.path(data_file_path,
  "The_Two_Towers.csv"),
  show_col_types = FALSE
)

return_king <- read_csv(
    file.path(data_file_path,
  "The_Return_Of_The_King.csv"),
  show_col_types = FALSE
)
```

Inspect one of the datasets:

```{r}
glimpse(fellowship)
```


See if the datasets contain the same information:

```{r}
names(fellowship)
names(two_towers)
names(return_king)

```


Each file contains the same variables but different observations. Stack them with `bind_rows()`. `bind_rows()` is a `tidyverse` (actually `{dplyr}`) function that binds any number of data frames together by row (i.e., stack them). The output will contain all columns that appear in any of the inputs. (There is also a function `bind_cols`).

Here, we combine the three dataframes together and then pipe the output into another function, `rename_with` to convert all column names to lowercase (using `str_to_lower`). 

```{r}
lotr_wide <- bind_rows(
    fellowship,
    two_towers,
    return_king) |>
  rename_with(str_to_lower)

lotr_wide
```

`bind_rows()` is appropriate because the tables have the same columns and each contains additional rows of the same kind of observation.

::: callout-warning
## `bind_rows()` is not a join

Use `bind_rows()` to stack similar observations vertically. Use a join (e.g., `left_join()` [which we will learn about later]) when separate tables contain different variables that must be matched using an identifier.
:::

### Tidy the gender columns

The columns `female` and `male` do not represent two different measured variables. They contain values of the variable `gender`. Their cells contain values of the variable `words`.

```{r}
lotr_tidy <- lotr_wide |>
  pivot_longer(
    cols = c(female, male),
    names_to = "gender",
    values_to = "words"
  )

lotr_tidy
```

What does one row represent before the pivot? What does one row represent afterward?
:::

<details>
<summary>Click to show the answer </summary>
Before the pivot: One row represents a unique combination of film and race, with the word counts for female and male characters stored in separate columns.

After the pivot: One row represents a unique combination of film, race, and gender, with the corresponding word count stored in the `words` column.

</details>

### Use the tidy data

To illustrate how useful tidy data is for working with the `{tidyverse}` packages, we will produce a summary of the number of words spoken by males and females. `group_by` is a function that groups a dataframe by the specified variable(s) so operations can be performed on a per-group basis. `summarize` (or `summarise` as the package developer is British) creates a new data frame that returns one row for each combination of grouping variables. If no grouping variables, the output will have a single row summarizing all observations in the input. Below, we use `group_by` and `summarize` to create a new column `total_words`.

```{r}
lotr_tidy |>
  group_by(gender) |>
  summarize(
    total_words = sum(words),
    .groups = "drop"
  )
```

## Part 4: Multiple variables encoded in column names {#sec-tb}

The tuberculosis dataset records confirmed cases by country, year, sex, and age group.

```{r}
tb <- read_csv(
    file.path(
        data_file_path,
    "tb.csv"),
  show_col_types = FALSE
)

tb
```

Inspect the column names.

```{r}
names(tb)
```

A name such as `m1524` contains two values:

``` text
m1524
|  |
|  └─ age group: 15–24
└──── gender: male
```

The column name is therefore a combination of two underlying variables: `gender` and `age`.

### Step 1: Pivot the case columns longer

Use similar code as before to reshape the data frame. `values_drop_na = TRUE` removes rows created by `pivot_longer()` when the value places in the cases column is `NA`. Without it, the long data would include combinations of country, year, and demographic group with missing case counts.

```{r}
tb_long <- tb |>
  pivot_longer(
    cols = -c(iso2, year),
    names_to = "demographic",
    values_to = "cases"
  )

tb_long

tb_long <- tb |>
  pivot_longer(
    cols = -c(iso2, year),
    names_to = "demographic",
    values_to = "cases",
    values_drop_na = TRUE
  )

tb_long
```

The new `demographic` column is still not tidy because each value combines gender and age.

### Step 2: Separate the encoded variables

The first character of `demographic` indicates `gender`, while the remaining characters contain the age code. We can separate these components using `separate_wider_regex()` from the `{tidyr}` package. This function splits a character column into multiple columns based on regular expression patterns. Regular expressions are patterns used to match specific arrangements of characters within text. Here, `"[mf]"` matches either `"m"` or `"f"`, and `".*"` matches all remaining characters. Related functions can instead split values at delimiters, such as commas, or at fixed character widths. 

```{r}
tb_tidy <- tb_long |>
  separate_wider_regex(
    demographic,
    patterns = c(
      gender = "[mf]",
      age = ".*"
    )
  )

tb_tidy
```

Now each underlying variable has its own column.

### Replace the gender codes

Abbreviations are not always so clear. Avoid if you can. Let's spell out what `m` and `f` mean. 

```{r}
tb_tidy <- tb_tidy |>
  mutate(
    gender = recode(
      gender,
      m = "male",
      f = "female"
    )
  )

tb_tidy
```

::: callout-note
## Observational unit

After tidying, one row represents the reported number of cases for one country, year, gender, and age group.
:::

The age codes can also be converted to readable labels, but we will leave that as an optional extension.

## Part 5: Exporting data frames {#sec-tb}

Use `write_csv()` from the `{readr}` package to save a data frame as a CSV file. The first argument is the data frame to save, and the second is the file path and filename. Unlike base R’s `write.csv()`, `write_csv()` does not add row names as an extra column.

```{r}
# create a path for the output file
output_file <- file.path(
  data_file_path,
  "lotr_tidy.csv"
)

# save the tidy data as a CSV file
write_csv(
  lotr_tidy,
  output_file
)

# check that the file exists
file.exists(output_file)

```

### Which function would you use?

| Situation                               | Function                 |
|-----------------------------------------|--------------------------|
| Read a CSV file                         | `read_csv()`             |
| Inspect column types                    | `glimpse()`              |
| Stack the same kinds of observations    | `bind_rows()`            |
| Move column names into rows             | `pivot_longer()`         |
| Split one encoded column into variables | `separate_wider_regex()` |

### Questions to ask before tidying

1.  What are the variables?
2.  What does one observation represent?
3.  Are variable values stored in column names?
4.  Does one column contain multiple variables?
5.  Are observations unnecessarily split across multiple tables?

## Optional extension: Widening data

`pivot_wider()` performs the opposite transformation. It takes values from rows and uses them to create columns.

```{r}
words_by_gender <- lotr_tidy |>
  group_by(film, gender) |>
  summarize(
    total_words = sum(words),
    .groups = "drop"
  )

words_by_gender |>
  pivot_wider(
    names_from = gender,
    values_from = total_words
  )
```

Wide data are not inherently bad. They can be convenient for presentation, data entry, or matrix operations. Long tidy data are generally easier to transform, summarize, and visualize with tidyverse tools.
